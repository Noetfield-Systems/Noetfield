Case 001 · Agentic coding reliability

Green Tests, No Page

An evidence-based study of agent-assisted software delivery. One repository. One customer goal. Multiple AI-assisted change sets. We compared what each session changed, what internal tests reported, and what the customer actually received.

Classification: OWNER-OBSERVED + PROVEN mix Repo: NOETFIELD-RUNWAY Product: Company New / app.noetfield.com Not a universal tool scorecard

1 — Same customer goal

Sign in to app.noetfield.com, type a normal sentence to the front person (named business or trade description), receive a public landing page in about a minute with plain client copy — no pipeline jargon, no false “passed quality check” while publish failed.

Acceptance contract (customer path): signed-in E2E → agent reply without gate codes → build completes → unauthenticated HTTP 200 on public preview URL → correct entity or trade on page.

9 — Methodology and limitations

  • Live E2E against production app.noetfield.com with fresh test accounts; receipts filed under the app postmortem path.
  • Attribution from GitHub co-author metadata and session labels — not a controlled multi-tool benchmark.
  • Public record redacts project and session IDs; uses project_ref_sha256 only.
  • Unsourced aggregate commit counts (e.g. unsourced “motor moved N commits”) are omitted.
  • Dollar cost and token spend for failed retries: UNKNOWN in this bundle.
